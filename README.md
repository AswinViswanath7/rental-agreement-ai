# RentEase — Rental Agreement Analysis

RentEase analyzes rental agreements and produces **evidence-backed**
findings: every rent amount, date, deposit, clause stance and risk is tied to
a verbatim quote from the contract text, verified by code. If a value cannot be
proven against the document, the system says so and flags it for human review
rather than guessing.

**Not legal advice.** This is information to help you read the contract. It is
not a substitute for a qualified lawyer or your local rent authority.

## Design goal: no silent mistakes

A wrong value shown with confidence is treated as a release-blocking bug.
Every user-visible fact carries evidence (`quote`, `page`, `char_start`,
`char_end`) that code verifies against the normalized source text. Numbers are
never generated by a language model — they are parsed deterministically into
typed values (`Decimal` + ISO currency, ISO date, integer months/days) and
rendered from those values.

Every field and clause has a status in
`found | not_found | ambiguous | needs_review | conflict`. Conflicting amounts
(for example figures vs words) are shown side by side with both quotes; they
are never silently resolved by first-match.

## Core pipeline (`app_core/`)

1. **Ingest** — PDF, DOCX, DOC (LibreOffice), JPG, PNG, TIFF, HEIC. Validates
   by magic bytes and by opening with the real parser; rejects polyglots and
   zip bombs; per-page OCR at 300 dpi only when needed; password detection;
   size/page/time limits; typed errors (never leaked to the client).
2. **Normalize** — Unicode NFKC, hyphenation fix, header/footer dedup, offset
   map back to page/original position.
3. **Segment** — clauses/headings/sentences with a legal abbreviation list; no
   segment cap (streams 200+ page documents).
4. **Classify (gate)** — whole-document rental vs non-rental classification with
   calibrated threshold (>= 99% precision target). Non-rental documents are not
   run through rental risk rules.
5. **Extract fields** — deterministic candidate finder (all candidates, never
   first-match) + LLM adjudication by candidate ID + code verification +
   cross-checks (rent vs words, dates vs term, deposit months).
6. **Clause analysis** — stance `present | absent | negated | conditional` with
   evidence strength; coverage report.
7. **Risk engine** — versioned YAML rules applied to verified fields/clauses;
   the report calculator counts flagged findings by severity, with no invented
   overall score or legal assessment.
8. **Summary** — built from verified fields with per-sentence evidence footnotes.
9. **Q&A agent** — server-held document; browser sends only session id +
   question; verified citations; deterministic calculator; abstains when
   evidence is missing.
10. **Translation** — placeholder-locked structured translation with
    placeholder verification.
11. **Report** — server-side PDF from the stored result, Unicode fonts,
    XML-escaped, no invented score, disclaimer.
12. **Learning loop** — consented, redacted corrections; review queue;
    promotion gate; never retrains from live uploads.

## LLM provider abstraction

`LLMClient.generate_structured(schema, system, user, max_tokens)` with retry on
schema failure (max 2) then `needs_review`. Implementations:
- Anthropic (`ANTHROPIC_API_KEY`, temperature 0)
- OpenAI-compatible local endpoint (`LOCAL_LLM_URL`) — fully offline
- NVIDIA NIM (`NVIDIA_API_KEY`, `NVIDIA_MODEL`; defaults to Nemotron 3 Ultra)
- `NO_LLM` (default) — deterministic + embedding only, lower coverage, still correct

All providers pass through the same verification layer. Prompts, schemas,
rules and thresholds are versioned and stamped on every result.

## Privacy by default

- Uploads processed in memory / per-request temp dir, deleted in `finally`.
- Document text, file names and personal data are **never logged**.
- Vendor Chart.js and Font Awesome served locally (no CDN).
- External LLM provider shows a visible notice that text is sent to that
  provider.
- Results deleted after a configurable TTL (default 1 hour); "Delete my data"
  removes the result, chat and feedback.
- Learns only from explicit, consented corrections.

## Security

- Application factory, blueprints, config from environment, typed settings.
- CSRF (Flask-WTF style) on all POSTs; rate limiting per IP/session; security
  headers (CSP without inline script, `X-Content-Type-Options`,
  `frame-ancestors none`, `Referrer-Policy`); secret key from environment.
- Errors return `{error_code, message, request_id}` — never `str(e)`.
- JSON bodies validated by schema.

## Quick start

```powershell
# 1. Create a virtualenv and install dependencies
python -m venv .venv
# Windows PowerShell:
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# 2. Configure (optional). Defaults to NO_LLM mode (no external calls).
$env:LLM_PROVIDER = "none"          # none | anthropic | openai_compatible | nvidia
# For NVIDIA NIM, set these locally after creating a replacement API key:
# $env:LLM_PROVIDER = "nvidia"
# $env:NVIDIA_API_KEY = "<your NVIDIA API key>"
# $env:NVIDIA_MODEL = "nvidia/nemotron-3-ultra-550b-a55b"
$env:FLASK_SECRET = "change-me"     # required in production
$env:MAX_UPLOAD_MB = "16"
$env:RESULT_TTL_SECONDS = "3600"
$env:ADMIN_API_TOKEN = "set-a-long-random-review-token"

# 3. Run
python -m flask --app app run --debug
# http://127.0.0.1:5000
```

When `LLM_PROVIDER=nvidia`, agreement text is sent to NVIDIA NIM for model
assistance. Keep the key in an environment variable or secret manager, never in
source code, screenshots, or chat. Revoke any key that has been exposed.

On Windows, start RentEase with a replacement NVIDIA key using the local,
non-persistent prompt:

```powershell
powershell -ExecutionPolicy Bypass -File .\run_rentease_nvidia.ps1
```

The script prompts for the key without displaying or saving it, then starts
RentEase on `http://127.0.0.1:5000`. Keep that terminal open while using the
app; press Ctrl+C to stop the server. The exposed key must be revoked first.

The home page includes an optional property-document comparison for two or
three files. It compares only clearly labeled values found in the documents
and recognizes common field labels in English and Indian languages. Unicode
values and digits are compared as written; documents are not translated, and
the comparison cannot verify ownership, title, authenticity, or legal status.
Analysis reports also include an evidence-linked review checklist and contract Q&A;
questions accept free-form follow-ups, keep a short server-side conversation,
and ask the configured model to reply in the question language or selected UI
language. Agreement-specific answers cite excerpts; unrelated general answers
are distinguished from contract facts. Multilingual/open-ended replies require
a configured LLM provider; without one, only deterministic English field
lookups and calculations are available. These tools are part of the existing
RentEase pages and do not provide legal advice.
The comparison area follows the selected interface language. It recognizes
common English and Indian-language labels for survey/document numbers, owner,
address, extent, and village details. Source text and values remain unchanged:
it does not translate documents or transliterate names between scripts.

The home page also includes a searchable reference imported from
`app_core/property_law_database.json`, converted from the supplied workbook.
It contains 36 central-law entries, 36 state/UT summaries, 31 clause benchmarks,
and 8 source entries. The workbook states that it was compiled from general
legal knowledge, is not a live legal-database pull, and needs verification
against current official sources. The reference is displayed for research only:
it is not used to generate agreement findings, legal conclusions, or risk scores.
Low-confidence entries are visibly marked.

## Public deployment

The Dockerfile is intended for a managed container host. Configure
`FLASK_SECRET` with a newly generated, persistent random value and keep
`DEBUG=false`; the container enables secure session cookies by default and
expects the host to provide HTTPS. Keep one application instance: jobs,
results, and chat sources currently live in process memory, so multiple workers
or instances cannot reliably share them, and a restart clears active reports.
The image includes OCR engines and fonts and may need more memory than a basic
static-site plan provides.

After deployment, attach the domain in the host's dashboard and follow its DNS
instructions. A dynamic-DNS updater for a home router does not deploy the app;
for a managed host, use the DNS target it provides rather than pointing the
domain at a personal computer. Never put DNS API keys or application secrets
in the repository or share them in screenshots.

The interface language can be changed from the selector in the navigation and
is remembered in the browser. The UI includes the 22 languages in India's
Eighth Schedule. The document-language selector also lists these 22 languages
and English using native names and language codes. This source-language choice
is separate from interface language and report translation. The selected code
is submitted with the upload, but the current analysis/OCR pipeline does not yet
use it to switch recognition behavior or translate the document. Document text,
extracted values, and contract evidence remain in their source language so
quotes are not altered.

The built-in correction loop is deliberately review-based: corrections are
stored only with explicit consent, redacted, and pending until an administrator
approves them. Approved quote patterns can guide later candidate selection;
corrected values are never copied into another contract's results. The review
queue is in memory and is cleared when the process restarts. Configure
`ADMIN_API_TOKEN` to use the `/api/admin/corrections` endpoints; without it,
review endpoints are disabled. Set `ADMIN_API_TOKEN` to a strong random value
and use bearer-token authentication for review requests.

## Evaluation

```bash
make eval        # runs the full evaluation harness; exits non-zero if any gate fails
make test        # unit tests
make lint        # ruff
make mypy        # type check
make ci          # lint + mypy + tests + eval
```

The evaluation harness (`eval/harness.py`) uses a deterministic synthetic gold
set with a frozen 70/30 dev/held-out split and measures per-field precision,
recall, F1, wrong-but-shown rate, abstention rate, evidence validity, and
classification gate precision. `make eval` writes `eval/report.md` and
`eval/results.json`.

## Acceptance gates (measured on held-out set)

| Gate | Requirement | Measured | Status |
|------|-------------|----------|--------|
| G1 | Critical-field wrong-but-shown <= 0.5% | 0.0% | Pass |
| G1 | Critical-field recall (clean) >= 95% | 100% | Pass |
| G2 | Evidence validity 100% | 100% | Pass |
| G4 | Rental precision >= 99% | 100% | Pass |
| G4 | Non-rental FP rate <= 1% | 0.0% | Pass |

**Note:** These numbers are from the deterministic synthetic gold set. Several
gates (G3 number-integrity, G5/G6 measurement, G7/G8 full security/privacy
penetration, G9 performance, G10/G11/G12) are implemented but were not fully
measured in this environment (no tesseract/scan corpus, no translation-model
measurement, no operator-confirmed legal rules, no real scanned PDFs). See
`docs/DECISIONS.md` and the "Known limits" section of `eval/report.md`.

## Known limits

- Legal risk rules are unconfirmed placeholders (`source_url: TODO`) pending
  primary-source confirmation by the operator. Do not treat them as legal
  advice.
- Document translation: only English is enabled by default; other languages require
  measurement (number preservation 100%, back-translation threshold) before
  being enabled.
- OCR/tesseract language packs and Noto fonts must be installed in the
  deployment (see Dockerfile).
- Performance targets (sub-30s one-page scan, sub-60s 10-page text PDF) are
  not yet measured on target hardware.
